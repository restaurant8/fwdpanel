# 转发面板（MVP）

一个从零实现的端口转发管理面板，功能上参考了 nyanpass 文档里描述的核心部分。代码为原创实现。

```
backend/     面板后端   Go + Gin + Gorm (SQLite)，只提供 API，也可顺带托管前端
frontend/    管理界面   TypeScript + Vite + React + antd
nodeclient/  节点端     Go，仅标准库；同一个程序可做入口或出口
scripts/     build.sh 构建，demo.sh 本机演示
```

## 已实现

**界面**：顶栏 + 侧栏布局，页面与路径：主页、个人中心、转发规则、商城、我的订单、节点状态，
以及管理端的仪表盘、站点设置、推送通知、用户管理、用户组管理、订单管理、套餐管理、兑换码管理、设备组管理、邀请记录。支持深色模式。

**用户与权限**
- 注册/登录、封禁、流量上限、到期时间、最大规则数、钱包余额与备注（仅记录）
- 用户组：设备组可以只开放给指定的用户组 ID
- 用户级限速、IP 数限制、连接数限制；规则级限速、IP 限制、连接数限制（每个入口节点单独计算）
- 管理员新建用户只填用户名，密码随机生成并显示一次；可重置密码

**用户自带出口**（单端隧道）：站点设置里开启后，用户可以在个人中心添加自己的出口并对接自己的机器，只有本人能用，不计倍率

**设备组**（四种类型）
- 仅监控：节点只上报探针数据
- 入口：限制出口、连接地址（展示用）、端口范围、直接转发策略（禁止/可选/强制）、屏蔽 UDP（高级编辑）
- 出口：限制入口、协议（tls_simple / ws / http）、故障转移组；隧道端口自动分配，可在高级编辑里修改
- 链式出口：虚拟组，配置 1~3 跳出口（入口 → 第 1 跳 → … → 最后一跳 → 目标），按链式出口自身的倍率计费
- 对接：在线安装命令、离线部署包（linux amd64 / amd64v3 / arm64）、重置 token
- 高级设置（列表里的齿轮按钮，文档中也叫"高级编辑"/"高级配置"）：IPv6 优先、强制 IPv4/IPv6、反向隧道、入站屏蔽、TLS 入站策略、隧道端口等都可以直接点选，
  不用手写配置；需要时可切到 JSON 视图查看或修改原始配置

**转发规则**
- TCP + UDP，指定或随机端口，多目标（随机 / 轮询 / 故障转移）
- 直接转发与隧道转发；出口组内按最小连接数均衡，全组不可用时切到故障转移组
- 接受 / 发送 Proxy Protocol（v1、v2，仅 TCP）
- TLS 入站：独立规则（入口终结 TLS，校验 SNI/ALPN，可自带证书）、母规则 + 子规则（多条规则共用一个端口，按 SNI 分流）；
  入口可设置 `tls_inbound_policy` 和 `tls_reject_empty_sni`
- 规则分组、搜索、排序、多选、批量导入/导出/切换、清空流量、删除选中

**节点**
- 探针页：按设备组显示节点的速率、流量、CPU、内存、存储、开机时长（完整数据仅 Linux）
- 节点备注：同一个设备组里有多台机器时，管理员可以在探针页给每台机器单独写备注，显示在节点名称下面
- 探针页可以设置出口节点的负载均衡权重（优先于节点启动参数 `-weight`）；鼠标移到速率上显示 TCP 连接数和 UDP 会话数
- 探针 API：每个用户在探针页点「API」生成自己的密钥后，外部程序可以读取他能看到的探针数据；管理员的密钥还能设置出口权重、升级节点（见下文「探针 API」）
- 在线终端：管理员可在探针页打开节点机器的 shell。用安装脚本对接的节点默认开启；安装命令前加 `TERMINAL=0` 则不开启（用户自带出口的安装命令默认带了它）
- 规则改动通过长连接立即推送到节点；节点与面板失联时按上一次的配置继续运行
- 连接复用：入口到每个出口只保持一条隧道连接，新连接不用再握手（出口高级配置 `mux: false` 可关闭）
- 出口故障判定：连续失败 `max_fail` 次后在 `fail_timeout_sec` 秒内不再使用；每 10 秒主动探测一次
- 节点 IP：节点自己探测公网 IPv4 并上报（网卡上没有公网地址时向 ipify 等公共服务查询），面板优先用上报的地址，
  所以节点与面板同机（用 127.0.0.1 对接）、面板在 CDN 或反代后面、节点经代理访问面板时，显示和下发的仍是节点的真实地址；`-advertise` 优先级最高
- 出口节点可单独指定隧道端口（`-tunnel-port`）和权重（`-weight`，或在探针页设置）；组内按「连接数 / 权重」最小优先，相同时按权重随机；出口组可设置静态连接地址和 ws 的 host/path（经 CDN、NAT 时用）
- 入站屏蔽（入口高级配置）：`blocked_protocol`（socks/http/tls）、`blocked_host`、`allowed_host`、`blocked_path`
- IPv6：节点自动探测并上报公网 IPv6。入口组高级配置 `ipv6_group` 指定连接哪些出口时优先用 IPv6（没有则回落到 IPv4）；
  出口组 `connect_type` 设为 `dyn_ip6` 强制用 IPv6（不回落），`dyn_ip4` 强制用 IPv4
- 反向隧道（内网穿透）：出口在内网时由出口主动连到入口。入口节点启动加 `-rev-port 端口`，入口组高级配置里设置 `reverse_group`
- 规则诊断：让入口节点按真实转发路径连一次目标，返回耗时
- 远程升级：探针页对版本落后的节点显示升级按钮，节点从面板下载新版本后原地重启
- 环境变量：`DISABLE_EXECUTE`、`BIND_INBOUND`、`BIND_OUTBOUND_4/6`、`OUTBOUND_FWMARK`、`COUNT_INTERFACE`、`HEALTH_CHECK`、`UUID`、`NYA_PROXY`
  （写在节点安装目录的 `env.sh` 里，然后重启服务）
- 配置文件模式：不带参数启动时读取当前目录的 `config.yml`（`base-url`、`token` 等）

**面板运维**
- 数据库：SQLite（默认），或 `-db mysql://...` / `-db postgres://...`
- 命令行：`-reset-password 用户名`、`-clean 1|2`、`-copy-database 连接串`
- 登录/注册频率限制（`-login-rate`，默认 5 次 / 5 秒，按 IP）；登录后接口可选限制（`-user-rate`）
- 节点离线判定时间（`-offline-node-time`）和离线记录保留时间（`-offline-node-retention`）

## 商城、支付与通知

**套餐与订单**
- 用钱包余额购买套餐：月付/日付（替换当前套餐，重置流量，设置到期时间）、不限时流量包、可叠加流量包（在现有额度上加流量）
- 兑换码（按折扣比例购买对应套餐，次数用完失效）、续费、自动续费（到期前 24 小时或流量用完时用余额续费）
- 订单：用户看自己的，管理员看全部；手动记账可加减用户余额；管理员可直接给用户指定套餐

**在线充值**（站点设置 → 支付设置里添加通道）

| 类型 | URL 填法 | PID | Secret |
|---|---|---|---|
| epay | `https://域名/submit.php`，或 `https://域名/mapi.php?type=alipay&device=pc` | 商户 ID | 商户密钥 |
| epusdt | 完整的下单接口，如 `https://域名/api/v1/order/create-transaction` | 不填 | Api Token |
| tokenpay | `https://域名/CreateOrder?currency=USDT_TRC20` | 不填 | Api Token |
| cryptomus | 可带参数 `?currency=CNY&subtract=0`（域名部分不使用） | merchant-id | payment-key |

- 回调地址由面板自动生成（`/api/v1/guest/pay/notify/订单号`），面板需要能被支付网关访问到；面板在反代后面时请填"回调 Host"。
- 回调会验签并核对金额，同一张订单只入账一次。费率是用户额外承担的手续费百分比。
- `cyber` 类型没有实现（没有找到它的协议说明）。
- **这些对接只用模拟网关测试过，没有用真实的商户账号验证。上线前请先用小额实测一遍。**

**邀请返利**：启用后用户在个人中心有邀请链接；被邀请人充值到账时邀请人按比例获得余额（可设是否循环返佣、是否要求绑定 Telegram）。

**Telegram 推送**：在「推送通知」里填 Bot Token 并保存，面板会自动注册 Webhook。用户在个人中心关联后可收到套餐到期、流量用尽、返利到账的提醒；
管理员会收到设备离线/恢复的通知，离线宽限期可按全局或设备组设置。服务器连不上 Telegram 时可用环境变量 `TG_API_BASE` 指定反代地址。

## 部署

### 1. 安装面板（在面板服务器上，一条命令）

不需要自己编译。以 root 运行：

```bash
bash <(curl -fLSs https://github.com/restaurant8/fwdpanel/releases/latest/download/install.sh)
```

脚本会按机器架构（amd64 / arm64）从 GitHub Releases 下载最新的发布包并安装。后面可以直接跟参数，例如 `... install.sh) -domain 你的域名`。
升级也是再运行一次这条命令。`VERSION=v0.9.0` 可安装指定版本。

服务器连不上 GitHub 时，在 Releases 页面下载对应架构的包传上去，然后：

```bash
tar xzf fwdpanel_linux_amd64.tar.gz && cd fwdpanel && bash install.sh -domain 你的域名
```

### 2. 发布新版本（维护者）

推送一个 `v` 开头的标签，GitHub Actions（`.github/workflows/release.yml`）会自动构建并发布到 Releases：

```bash
git tag v0.9.0 && git push origin v0.9.0
```

面板是**单个可执行文件**，前端页面和三种架构的节点端安装包都已内嵌在里面。
想在本机自己构建时运行 `scripts/build.sh`，产物在 `release/`。

安装脚本的说明：

- 不带参数时是**引导模式**，会一步步询问用域名还是端口；带参数则不提问，适合自动化。
- `-domain 域名`：自动申请并续期 HTTPS 证书，监听 443/80。域名需要已解析到这台服务器。使用此参数即表示同意 Let's Encrypt 的服务条款。
- 不带参数：HTTP，监听 8080；`-port 9000` 可换端口。
- 脚本会注册 systemd 服务 `fwdpanel`，装完打印面板地址和管理员初始密码。
- 已经装过时不带参数再运行一次即为升级，保留原来的域名/端口设置；数据在 `/opt/fwdpanel/data`，备份这个目录即可。

### 3. 对接节点（在节点服务器上）

登录面板 →「设备组管理」→ 添加设备组 → 点「对接」→ 复制在线安装命令，到节点机器上以 root 运行。
同一条命令可以在多台机器上运行，它们共用这个组的规则。

- 节点机器连不上面板下载时，用「对接 → 离线部署」下载对应架构的 `.tar.gz` 包，传上去后按弹窗里的命令解压并运行 `install.sh`。
- 在安装命令后面可以追加节点端参数，例如 `-advertise 1.2.3.4`（出口对外地址）。在线终端默认开启，不需要时在命令最前面加 `TERMINAL=0`。
- 在终端里直接运行时会询问服务名；如果已经装过，可以选择"只升级程序"或"重新安装"。
- 引导模式下还会询问是否**优化系统网络参数**（开启 BBR + fq，调大 TCP/UDP 缓冲区、连接队列、本地端口范围和文件句柄数，
  写入 `/etc/sysctl.d/99-fwdnode.conf`）以及是否安装常用工具（mtr、htop、iftop、nload 等）。不提问时用 `OPT=1`、`TOOLS=1` 打开。
- 不想被提问、或同一台机器装多个节点：命令前加 `S=名字`，例如 `S=node2 bash <(curl ...) ...`。
- 日志 `journalctl -fu nodeclient`，卸载 `bash /opt/nodeclient.uninstall.sh`。

```bash
scripts/demo.sh
```

启动面板（127.0.0.1:8080）、一个测试目标，以及 `demo/tokens.txt` 里列出的本机节点。管理员密码在 `demo/admin-password.txt`。

## 工作方式

节点每 10 秒向 `POST /api/v1/node/sync` 上报状态、探针数据和流量增量，面板返回该节点当前应生效的全部规则，节点据此增删监听。
节点同时保持一条到 `/api/v1/node/ws` 的长连接，面板有改动时通过它通知节点立即同步，在线终端也走这条连接。

隧道握手是一行 JSON（规则 ID、目标、时间戳和签名）。签名是用隧道密钥做的 HMAC，密钥本身不在线路上传输；
出口只会连接面板下发给它的规则里的目标。入口和出口的系统时间相差不能超过 2 分钟。
UDP 经隧道传输时每个包前加 2 字节长度。

## 探针 API

给监控脚本、机器人等外部程序用。每个用户有自己的密钥：登录后在探针页右上角点「API」生成（可随时重置或停用），
请求时带上请求头 `X-API-Key: 密钥`（或 `Authorization: Bearer 密钥`）。
密钥代表这个用户，能读到的内容和他在探针页看到的一样（普通用户看不到节点 IP，也看不到对他隐藏的设备组）；
设置权重和升级节点只有管理员的密钥可以。密钥只能访问下面这几个接口，不能用来登录。

| 接口 | 谁能用 | 作用 |
|---|---|---|
| `GET /api/v1/open/status` | 所有用户 | 设备组和节点：在线状态、备注、版本、连接数（`conns_tcp` / `conns_udp`）、权重，以及速率、流量、CPU、内存、存储、开机时长 |
| `GET /api/v1/open/nodes/:id` | 所有用户 | 单个节点，附带所在设备组的名称和类型 |
| `PUT /api/v1/open/nodes/:id/weight` | 管理员 | 设置出口权重，请求体 `{"weight": 5}`；`0` 恢复默认 |
| `PUT /api/v1/open/nodes/:id/note` | 管理员 | 设置节点备注，请求体 `{"note": "洛杉矶 CN2"}`；空字符串清除 |
| `POST /api/v1/open/nodes/:id/upgrade` | 管理员 | 让在线的节点升级到面板内置的版本 |

```bash
curl -H "X-API-Key: 密钥" http://面板地址/api/v1/open/status
```

出错时返回 `{"error": "原因"}`：密钥无效或账号被封禁 401，不是管理员 403，节点不存在或无权查看 404。连续用错误的密钥请求会被限频（429）。

## 部署前请注意

- 面板本身是 HTTP。对接密钥和登录会话都走这条连接，公网部署请放在 HTTPS 反向代理之后，
  并在 `backend/main.go` 的 `SetTrustedProxies` 里填入代理地址，否则节点 IP 会显示为代理的 IP。
- tls 隧道使用出口自签证书的 TLS 1.3，入口不校验证书，只靠握手签名确认身份：能防被动窃听，不能防主动中间人。
- ws 隧道不加密，转发的内容在入口和出口之间是明文（密钥不会泄露）。需要加密请用 tls，或在 ws 前面自行加 TLS 反代。
- 在线终端等于把节点的 shell 交给面板管理员（以 nodeclient 进程的用户身份）。用安装脚本对接的节点默认开启：管理员账号一旦泄露，所有开启了终端的节点都会被控制，请务必保护好管理员账号；不需要终端的节点安装时加 `TERMINAL=0`，或在节点的 `env.sh` 里设置 `DISABLE_EXECUTE=1`。
- 支付通道的密钥、Telegram Bot Token 明文保存在面板数据库里，请保护好数据库文件和备份。
- 请只在你有权管理的服务器和网络上使用，并遵守所在地的法律法规。
